# 게슈탈트 UI 설계

사용자가 화면을 처음 봤을 때 무엇이 한 묶음이고 무엇을 눌러야 하는지 바로 보이게 만든다. 기준은 근접성·공통 영역·유사성·전경과 배경 네 가지이고, 아래 규칙은 모두 결과 화면에서 확인할 수 있는 조건으로 적었다.

## 모드

| 상황 | 모드 |
| --- | --- |
| 시안 없이 화면·컴포넌트를 새로 만들거나 고친다 | 생성: 규칙을 적용하고 렌더링으로 확인한다 |
| 디자인 리뷰, 시안 검토, "이 화면 어때?" | 제안: 파일을 고치지 않고 아래 형식의 의견만 낸다. 시안이 있는 화면이어도 리뷰 요청이면 이 모드다 |
| 피그마 시안이나 디자인 시스템을 따라 구현한다 | 쓰지 않는다. 시안과 토큰이 정본이다 |

## 규칙

**근접성**
- 그룹 안 간격은 그룹 사이 간격보다 작다. 라벨-입력처럼 한 덩어리인 요소는 같은 그룹의 다른 항목 사이 간격보다 가깝다.
- 간격은 4 또는 8 배수 스케일에서 고르고, 간격과 색은 CSS 변수나 프로젝트 토큰 한 곳에 정의해 참조한다. 컴포넌트 크기와 테두리 두께는 직접 명시해도 된다.

**공통 영역**
- 간격만으로 그룹 경계가 안 보이면 카드, 배경색, 구분선 중 하나로 묶는다. 같은 수준의 그룹들은 같은 방식으로 묶는다.
- 탈퇴·삭제처럼 되돌릴 수 없는 액션은 일반 액션과 다른 영역에 두고, 실행 전에 확인 단계를 둔다.

**유사성**
- 동등한 선택지(칩, 탭, 세그먼트, 라디오)는 같은 컴포넌트와 같은 크기를 쓴다.
- Primary 액션은 레이어(본 화면, 모달, 시트)마다 하나이고 Filled로 둔다. 나머지는 Outline·Ghost·텍스트 버튼으로 낮춘다.
- 파괴적 액션은 Primary 색을 쓰지 않는다.

**전경과 배경**
- 딤은 뒤 화면 조작을 막는 모달·바텀시트·전체 화면 팝업에만 쓴다. 토스트, popover, 툴팁, 비모달 시트에는 쓰지 않는다.
- 이미지나 그래픽 위 텍스트와 닫기 버튼은 배경 대비 WCAG 4.5:1(18px 이상 굵은 글자는 3:1)을 넘긴다. 이미지 색을 모르면 가장 밝은 경우(흰색)로 계산하고, 부족하면 그라디언트나 반투명 레이어를 깐다.

## 생성 모드 순서

1. 화면의 Primary 액션 하나와 정보 그룹을 먼저 정한다.
2. Mobbin MCP가 연결돼 있으면 `search_screens`로 같은 종류의 화면을 1~2개 찾아 배치 패턴만 참고한다. 없으면 이 단계를 건너뛴다.
3. 위 규칙대로 구현한다.
4. 브라우저에서 모바일 폭(375px 전후)으로 열어 스크린샷을 찍고 확인한다. 그룹 경계, Primary 액션, 파괴적 액션의 분리가 스크린샷만 보고 구분되지 않으면 고친다. `file://`이 막히면 로컬 http 서버로 연다. 브라우저 도구가 없으면 확인하지 못했다고 보고한다.

## 제안 모드 형식

이 스킬은 리뷰의 한 관점이다. 기능 버그, 접근성, 문구 같은 다른 지적은 평소대로 하고, 이 스킬의 의견은 그 뒤에 「게슈탈트 제안」 섹션으로 덧붙인다. 시안이나 디자인 시스템이 있는 화면이면 섹션 제목 옆에 「시안 의도 확인 필요」를 한 번 붙이고, 간격 스케일과 CSS 변수 규칙은 시안 값이 정본이므로 지적하지 않는다.

의견은 영향이 큰 순서로 5개 이내로 낸다. 각 의견은 다음 네 줄로 쓴다.

```text
[제안] <원칙>: <화면 위치>
관찰: <지금 상태>
제안: <바꿀 방향>
근거: <사용자나 유지보수에서 생기는 문제>
```

해당하는 의견이 없으면 섹션에 「제안 없음」 한 줄만 쓴다.
