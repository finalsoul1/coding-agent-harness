# 보고서 HTML 양식

같은 디렉터리의 `template.html`이 양식 정본이다. 보고서를 만들 때마다 이 파일을 복사해 내용만 바꾼다. 양식 자체를 바꾸고 싶으면 `template.html`을 고친다. 보고서 한 장에서만 스타일을 고치면 양식이 문서마다 달라진다.

## 절차

1. `template.html`을 읽는다.
2. 저장 위치를 정한다. 사용자가 말한 곳이 우선이고, 없으면 작업 중인 저장소의 문서 관례를 따른다. 둘 다 없으면 묻는다. 파일명은 `<주제>-YYYY-MM-DD.html`.
3. 복사본에서 아래 "바꾸는 자리"만 채운다.
4. 브라우저로 열어 확인한다. 스크롤하면 목차 강조가 섹션을 따라 바뀌는지, 가로 스크롤이 생기지 않는지 본다.

## 바꾸는 자리

| 자리 | 내용 |
|---|---|
| `<title>`, `.doc-head h1` | 보고서 제목. 관측값보다 조치나 결론을 쓴다 |
| `.sidebar-head .title` | 목차 위에 보일 짧은 제목 |
| `.sidebar-head .kicker` | 분류 표시. 기본 `REPORT`, 티켓이 있으면 티켓 번호 |
| `.sidebar-foot` | 작성자, 갱신 시각 |
| `.doc-head .meta` | 갱신 시각, 대상, 관측 기간 |
| `section[id]` | 본문. 섹션 하나에 `h2` 하나 |

갱신 시각은 실제 작성 시각을 `YYYY-MM-DD HH:MM KST`로 쓴다.

## 목차와 섹션

- 목차와 섹션 번호(`01`, `02`)는 스크립트가 `section[id]`의 `h2`에서 만든다. 목차 HTML을 직접 쓰지 않고, `h2`에 번호를 넣지 않는다.
- `id`는 영문 kebab-case로 쓴다. 링크 주소에 그대로 보인다.
- 섹션 구성은 내용 규칙을 따른다. 상급자 보고라면 `report-draft`의 블록(결론, 근거, 위험과 되돌리기, 확인하지 않은 것)을 섹션으로 옮긴다. 정해진 규칙이 없으면 템플릿의 예시 구성을 쓴다.

## 폭

- 글 폭은 `--measure`(720px), 문서 전체 폭은 `--wide`(1200px)다. 한글은 한 줄에 40~50자일 때 읽기 편해서 글을 따로 좁힌다.
- 문단, 목록, 상자, 표는 기본으로 글 폭이다. 열이 많은 표, 이미지 그리드, 단계별 스크롤 영역처럼 넓어야 읽히는 블록에만 `class="wide"`를 붙인다.

## 쓸 수 있는 블록

| 블록 | 용도 |
|---|---|
| `.box` + `.label` | 결론처럼 먼저 봐야 할 내용. 한 문서에 한두 개 |
| `table` | 숫자 열은 `class="num"`, 기준(평균, 기간)은 `caption`에 쓴다 |
| `details` + `summary` | 측정 방법처럼 접어 둘 근거 |
| `.scrolly` | 단계별 설명. `.step`의 `data-step`은 0부터, `.figure li` 개수를 `.step` 개수와 맞춘다. 필요 없으면 섹션째 지운다 |
| `ul.plain` | 일반 목록 |

## 바꾸지 않는 것

`<style>`과 `<script>`는 그대로 둔다. 목차 생성, 현재 섹션 강조, 사이드바 폭 조절(드래그, 더블클릭 초기화, 좌우 화살표), 모바일 목차가 여기 들어 있다. 사이드바 폭은 `report-sidebar-width` 키로 브라우저에 저장돼 이 양식을 쓰는 모든 문서가 같은 폭을 쓴다.

## 기존 HTML 문서를 이 양식으로 바꿀 때

기존 문서에 자체 스크립트(목차, 필터)가 있으면 이 템플릿으로 다시 쓰기보다 테마 CSS를 덧씌우는 편이 안전하다. 문서 사이트의 iframe 안에서 열리는 문서는 그 환경에서 목차 고정과 강조가 동작하는지 따로 확인한다.

## 주의

- 이 저장소에는 양식만 둔다. 내용을 채운 보고서는 여기에 커밋하지 않는다. 업무 보고서에는 사내 정보가 들어가기 때문이다.
- 폰트는 Google Fonts에서 불러온다. 막힌 환경에서는 시스템 폰트로 보이고 기능은 그대로다.
- 한글 문장은 `/korean-writing`으로 점검한다.
